# Patch series

Applied in lexical order on top of the pinned CrossOver 26.3 Wine source (`inputs.json`) by `build.yml`, for the Intel
line (`x64-crossover26.3-r*`). Most files start with a header stating what the patch fixes, how it was verified, and
where it stands upstream. A patch that upstream ships is deleted here in the same change that bumps the pinned source.

## At a glance

Kinds are explained in the [top-level README](../README.md#patches-at-a-glance). None of these has been sent to WineHQ
yet. The paragraphs under the table give the details and the measurements.

## Details

- `0001-use-the-real-user-name.patch`: CrossOver Hack 12735 names the Windows user "crossover" and hardcodes `C:\users\crossover`; Highball bottles carry `C:\users\<macOS user>`, and a bottle moved to this engine would get a second profile directory. Restores upstream Wine's behaviour in advapi32 and shell32. Verified 2026-09-04 (M1 Pro, macOS 26.6.2).

- `0002-wined3d-auto-renderer-opengl-first.patch`: CrossOver hack 18311 tries the Vulkan wined3d adapter first on macOS; with MoltenVK present it is created and then fails Direct3D 11 feature checks (Warframe's launcher, Rockstar's launcher). Upstream's OpenGL-first choice, which Sikarugir's engine shows in practice, restored; renderer=vulkan stays selectable.
- `0003-ntdll-winedllpath-prepend.patch`: WINEDLLPATH_PREPEND support (MacPorts GPTK patch 1005), without which none of Highball's renderer overlays applied on this engine.

- `0005-ntdll-yield-after-auto-event-set.patch`: after an auto-reset event goes 0→1 (msync) or the server reports a 0→1 set (sync=none), yield once so the woken waiter runs before the setter can signal again. Windows boosts the woken thread; without it a job hand-off that signals twice loses the second wake-up (CS:GO legacy's map-load freeze on macOS 26 under Rosetta, reproduced 2026-09-04).

- `0006-kernelbase-per-exe-command-line-append.patch`: `HKCU\Software\Wine\AppDefaults\<exe>\CommandLineAppend` (REG_SZ) is appended to that executable's command line at CreateProcess. Data-driven per-app switches for programs that never forward them to their subprocesses (a launcher's CEF browser: --log-severity, --log-file, GPU switches). Proton keeps a hard-coded table for the same purpose.

- `0007-winemac-cross-process-child-swapchains.patch`: implements Wine bug 60263 — a CEF GPU process (Rockstar/Ubisoft/Steam browser) presenting into a child window whose root belongs to another process gets a CAContext-exported offscreen Metal swapchain, hosted in the owning process via CALayerHost (WM_MACDRV_CREATE_REMOTE_LAYER). Supersedes the old 0004 overlay approach. Fixes the blank CEF sign-in / black Steam client.

- `0008-macos-mirror-teb-fiberdata.patch`: on macOS the %gs base is the host thread block, so signal_init_process() mirrors Tib.Self, ThreadLocalStoragePointer and Peb into it but not Tib.FiberData. GetCurrentFiber() is an intrinsic reading %gs:0x20 directly, so a fiber-based job system reads a host value (measured: a constant 0x8ff on every thread) and hands it back to SwitchToFiber, which faults. Mirrors the field in the three places kernelbase changes it (a mirror at thread start was dropped the same day, see the patch header). Measured on M1 Pro, macOS 26.6.2, engine x64-crossover26.3-r4, 2026-09-09; reproducers need no game. NOT yet verified to make Marvel's Guardians of the Galaxy run, and does not explain why CodeWeavers' own testers report that game working on M1 from this same tree. Upstream: not an upstream bug, since Wine 10.5 swaps the whole gs base (3a16aabbf5), which this tree does not have.
- `0009-macos-swap-fiberdata-and-qos-slot.patch`: on macOS %gs:0x20 is also the pthread QoS slot, so the slot is swapped between Tib.FiberData and the QoS value at every crossing instead of being mirrored once. 0008's mirror let fiber games read the real fiber but clobbered QoS for libdispatch and pthread (Metaphor: ReFantazio hung at full CPU with a black window on the engine with 0008 alone, M1 Pro, macOS 26.6.2, 2026-09-12).

- `0010-mfreadwrite-video-processor-sample-allocator.patch`: Proton 164af86d; the source reader lets the video processor's allocator create sample textures, so they carry the shared flags a DXGI device manager asks for and DXMT can hand a game (Unity, Unreal media players) a real shared handle instead of null (The Last Flame's menu video, highball#99; 3Shain/dxmt#135).

- `0011-macos-lasterror-in-gs-slot.patch`: %gs:0x68 is where MSVC-built code (Unity's Mono, 130 sites) reads GetLastError(); on macOS that is libc's TSD slot 13, so it is swapped at the 0009 crossings and kept in step with TEB->LastErrorValue by RtlSetLastWin32Error, and the readers use it. File.Delete on a missing save no longer throws "Unknown error (0x80f13910)" (The Last Flame, highball#99).

- `0012-ntdll-x87sidecar-cooperative-attach.patch`: athei's 335ebe1c46 (refreshed 2026-10-06). Two things. get_alternate_wineloader() now checks the loader it names with access(X_OK): our builds are wow64-only, the i386-unix loader does not exist, and without the check env.c's build_initial_params() took the phantom path as a reason to relaunch every 32-bit program through `start.exe /exec`, so each ran as a child of a detached start.exe (measured 2026-09-24: two processes without WINEARCH, one with). And with ROSETTA_X87_PATH set to athei's x87sidecar, an i386 program re-execs through it in cooperative mode, no entitlement needed: fsin/fsqrt/fdiv loop 1554 ms to 20 ms, Half-Life 2 timedemo 131 to 174 fps on wined3d (M1 Pro, macOS 27.0). The sidecar part is off unless the variable is set, the loader check is always on. Upstream: CrossOver-only hack by athei (github.com/athei/wine), not for WineHQ.
- `0013-ntdll-nx-compat-from-main-image-permanent-under-rosetta.patch`: athei's 539aa62. Wine turned data execution prevention off for the whole process as soon as any loaded module lacked IMAGE_DLLCHARACTERISTICS_NX_COMPAT, which sets force_exec_prot and adds PROT_EXEC to every readable mapping; under Rosetta a writable and executable page costs a Mach round trip on first touch, so an old game without the flag turns every allocation into a fault storm (athei/wine-build#3 measured a 190x frame time difference from one LoadLibrary). Now only the main executable's flag counts, as on Windows, and under Rosetta DEP is permanently on (ProcessExecuteFlags reports MEM_EXECUTE_OPTION_PERMANENT, SetProcessDEPPolicy off fails with STATUS_ACCESS_DENIED). WINE_DISABLE_NX_COMPAT=0 lets a program that really executes from data pages turn DEP off again, as Windows does, on any host. Suggested by athei on highball#165 (2026-09-25); dry-run applies on the pinned source. Trial build 2026-09-25 (run 36125101280): applies and builds; a 32-bit program without the flag reads ProcessExecuteFlags 0x9 on it against 0x2 on r11. No cost found to remove on M1 Pro / macOS 27.0: fresh-page touch, LoadLibrary/FreeLibrary, VirtualProtect churn and VirtualAlloc churn time the same with no-exec on and off, on r11 and on the trial. Shipped from engine r17 (2026-10-03). Upstream: athei's tree, not WineHQ.
- `0014-msync-unregister-early-return.patch`: msync_wait_multiple() registers the thread with the wineserver's msync thread for every object, then spins until the server answers; when an object became available during the spin it returned without unregistering, and the server kept the thread on each object's list. The server side also left object 0 registered when a registration met a signaled object at index 1. Nothing removed those entries, so a rarely signaled object gained a list node per lost race, the 524288-node pool ran out ("msync: warn: node memory pool exhausted" on every allocation after that, 242 million lines in one My Summer Car log) and the wineserver grew without bound (highball#224). Now the early return unregisters like every other exit, the server unregisters objects 0..i-1 for any i > 0, and the warning prints once. Measured 2026-10-01 on an M4, macOS 27.0, with a reproducer (a worker sets an auto-reset event in a loop while the main thread waits on {quit, work}): r12's wineserver went from 30 MB to 77 MB in 30 s and exhausted the pool, the build with 0014 stayed at 39 MB for 2 minutes with no warning and no slower waits (about 706k per second); Heartopia ran 90 s under msync on it with a steady wineserver. The build that carries it is engine-wine-11.0-20260930T215119Z-0014-msync-trial (run 36780162838, branch msync-trial: 0001-0012 and 0014, without 0013, which was held then). Upstream: msync is CrossOver's and Sikarugir's, not WineHQ's; Highball's Wine 10 engine had the same two faults in its prebuilt binaries, fixed there by byte edits (gin's Scripts/build-wine10-msync.sh, release wine10-msync-20261001, engines r17 and r18).
- `0015-winecoreaudio-io-buffer-under-half-a-period.patch`: the HAL output unit asked Wine's render callback for its whole I/O buffer at once, 512 frames, 10.7 ms at 48 kHz, longer than the 10 ms period a shared-mode client is woken for. A game that keeps about one period queued then had too little at most pulls and the callback played the rest as silence: Counter-Strike 2's menu music on an M4 at 48 kHz dropped out 324 times in two minutes on the default engine and 20 times in 95 s on r12, none with the output at 96 kHz (highball#127). A render stream now sets the unit's I/O buffer to half its period at the device's rate before initializing it, per process. Measured 2026-10-01: with this build's winecoreaudio.so over r12, none over the same 95 s. The build that carries it is engine-wine-11.0-20261001T024555Z-0015-coreaudio-trial (run 36806082052, branch audio-trial, 0001-0012, 0014 and 0015 without 0013, which was held then), shipped as Highball's engine x64-crossover26.3-r14. The default engines get the same cap from a library Highball inserts (gin's spike/audiobuf). Upstream: not reported yet.

- `0016-macos-lasterror-callback-return-once.patch`: the user-mode callback return no longer writes LastErrorValue back a second time. 0011's second write-back copied libc's slot into the TEB, so the first display call of a process left a heap pointer in GetLastError() and the Rockstar Games Launcher installer stopped (highball-db#272, M4, macOS 27.0, 2026-10-02).

- `0017-kernelbase-getintegrateddisplaysize-stub.patch`: upstream Wine c68ed23672 (Paul Gofman). The CrossOver 26.3 tree has no GetIntegratedDisplaySize export at all, so a program that imports it gets the loader's unimplemented-function thunk and dies on the call. Forza Horizon 6 calls it once its window is up (M4, macOS 27.0, r17 with D3DMetal 4.0b2, 2026-10-05). The stub returns E_NOTIMPL like upstream's, and the game accepts that.

- `0018-macos-commit-charge-is-the-footprint.patch`: fill_vm_counters() reported PagefileUsage (and so PrivateUsage) from the Mach task's virtual_size, which is address space; a 9 MB console program read 41,987 MB on an M4, unchanged after it committed 512 MB. It now reports the task's phys_footprint, the counterpart of the RssAnon + VmSwap sum the Linux branch uses. Forza Horizon 6 compared the old figure with physical memory and warned about low memory (87 GB / 32 GB) while its resident size was 5.8 GB (2026-10-05). Upstream has the same line; to send.

- `0019-advapi32-credenumerate-empty-keychain-is-not-an-error.patch`: CredEnumerateW() asks the registry, then the host's store through mountmgr, and on macOS mountmgr answers STATUS_NOT_FOUND when no Keychain item matches the filter. Only ERROR_NOT_SUPPORTED was forgiven, so a filter that matched registry credentials but nothing in the Keychain failed the whole call and the matches were dropped. The Xbox Live sign-in library looks its device key and tokens up that way (`Xbl|DeviceKey*`), never found them, made a new device key on every launch and asked the player to sign in again each time (Forza Horizon 6 on an M4, six device codes in one evening, 2026-10-05). An empty host answer now counts as no host credentials. Upstream has the same lines; to send.
- `0020-winemac-retina-horzres-not-doubled.patch`: HORZRES and VERTRES are not doubled in retina mode (from athei/wine fa43d6db2, LGPL). A retina process saw the screen twice as large there as through GetSystemMetrics, which cropped Red Dead Redemption 2 at 1920x1080 fullscreen (highball#261, M4, macOS 27.0, 2026-10-06).

- `0021-opengl32-es2-compat-calls-in-legacy-contexts.patch`: macOS lists GL_ARB_ES2_compatibility only in 4.1 core contexts, so in the legacy 2.1 context a program gets without attributes opengl32 withheld that extension's calls and returned nothing. Programs written against OpenGL ES 2 call them anyway, since Windows drivers offer them in any context. When the extension is missing, glClearDepthf and glDepthRangef now go through glClearDepth and glDepthRange, glGetShaderPrecisionFormat gives desktop answers, and glReleaseShaderCompiler and glShaderBinary do nothing, next to the existing RuneScape and Grim Fandango alternatives. Measured 2026-10-06 on an M4, macOS 27.0: Paperback: The Game (Loom engine, both builds) crashed at address 0 right after loading glClearDepthf (highball-db#349); its loader crashes on the first of the five calls it cannot get. With the patch both builds reach the title menu (trial runs 37484516462, 37487709180, 37490328119). Upstream: not reported.
- `0022-mmdevapi-spatial-static-object-order.patch`: spatial audio static objects get their channels in WAVEFORMATEXTENSIBLE speaker-bit order (back before side), and back centre's map entry lands at its own index. By Tx (TxCsOffc, highball#313).
- `0023-winecoreaudio-spatial-mixer-for-surround-beds.patch`: a float surround bed with more channels than the output device (Forza Horizon 6's 7.1.4 spatial audio on a Mac's two channels) goes through AUSpatialMixer instead of losing every channel but front left and right. HB_SPATIAL=0 turns it off, HB_SPATIAL=speakers|headphones|external overrides the output type. By Tx (TxCsOffc, highball#313).
- `0024-kernelbase-app-packages-from-the-registry.patch`: GetPackagesByPackageFamily, GetPackagePath and PackageFullNameFromId read the app packages registered in the registry (Paul Gofman's Proton code), and wine.inf registers the Visual C++ libraries package (Proton's entries). Forza Horizon 4 waited forever on the stub's empty answer (highball#268, Wine bug 55397).
- `0025-ntdll-threadpool-io-release-once.patch`: CloseThreadpoolIo and the I/O completion thread claim destruction of a threadpool I/O object once, under ioqueue.cs then the pool lock. A completion that is still expected keeps the object and still runs its callback; one that arrives after the object was freed is ignored. CancelThreadpoolIo no longer wraps pending_count. The old path asserted `ioqueue.objcount` at threadpool.c:2102 (Scam With Your Friends, Kolkata OS recording teardown, three times on 2026-10-18, engine x64-crossover26.3-r4, macOS 27). Verified the same day with a named-pipe reproducer on the rebuilt ntdll: immediate free, skipped completion, callback-after-release, and cancel racing a queued completion. Not yet run inside the game. The patch also updates the threadpool tests in `dlls/ntdll/tests/threadpool.c`. Upstream: Wine 11 and master still race; not sent. By Moritz Jost (jostmoritz, #17).
- `0026-ntdll-timezone-names-for-utc3-zones.patch`: the UTC+3 zones without daylight saving time join CrossOver's match_tz_name table, told apart by the host's zone abbreviation and its offset at a past date, so a Mac set to Europe/Istanbul names its zone Turkey Standard Time instead of Arab Standard Time (the first UTC+3 zone in the registry). Rockstar's sign in refused the Riyadh zone from Turkey with #1.000.7 (highball#477, #478); removing the earlier zones by hand let a reporter sign in. Moscow, Volgograd, Amman, Nairobi and Addis Ababa also get their own zones now; Riyadh, Baghdad and Minsk keep Arab Standard Time. Checked with a C copy of the matching on macOS 27. Upstream: not sent.
- `0027-ntdll-dll-redirection-dotlocal-folder.patch`: Windows' DLL redirection folder. When a folder named like the main exe with `.local` appended sits next to it, a DLL loaded by name is looked for there first, known DLLs excepted. Fahrenheit: Indigo Prophecy Remastered keeps its Qt5, SDL2, MinGW runtime and steam_api DLLs in `Fahrenheit.exe.local` and stopped before its first window in every graphics mode (highball-db#700). Full-path loads and the manifest rule are not handled. Checked with dltest.exe on the M4 (fails on r28 and r25 before the patch). Upstream: not sent.
- `0028-ntdll-crash-on-faults-in-foreign-threads.patch`: on macOS, segv_handler, trap_handler and fpe_handler first check NtCurrentTeb(). A thread Wine didn't create (a libdispatch worker running Metal or D3DMetal code) has none, and save_context would fault reading it at 0x2f0 and be retried forever; such a fault now restores the signal's default action and returns, so the process ends with SIGSEGV, SIGTRAP or SIGFPE and the crash report names the first fault. Threads with a TEB are unchanged.
